# Context, Google integration and workflow slice

The repository migrated `desktop/` to `apps/app/` during this task.

Implemented native path: Google Desktop OAuth authorization-code flow, system browser, random loopback port, state validation, S256 PKCE, 120-second authorization deadline. Refresh credentials and the desktop client configuration are saved only with keyring's Windows-native Credential Manager backend. Access tokens stay in Rust memory and are not returned to JavaScript. Requests use TLS and a 25-second timeout. Configure a Google Desktop client and enable Gmail and Calendar APIs; production consent/verification is the deployer's responsibility. Scopes: gmail.send and calendar.events.owned. Disconnect removes local credentials and attempts Google revocation.

Gmail sends immutable reviewed recipient/subject/body using messages.send. Its returned message ID is an acknowledgement, not proof of delivery; the send-only scope cannot read back Sent. Calendar inserts into the primary calendar with a client-generated event ID and verifies by GET. No attendees are added. Real OAuth and provider paths compile but have not been exercised with a live account.

Sandbox previews and confirmations use the same native validation and single-use preview store, but make no provider writes. UI explicitly identifies sandbox. Previews expire after five minutes. Real writes first create a durable content-hash guard in app data; identical actions remain blocked across restart, including ambiguous network failures. There is deliberately no automatic remote-write retry. Reconcile provider state before manually removing a guard. Guards contain no recipient/content, but their hashes can still reveal repeated content. Disconnect does not clear them.

ContextSession rejects stale windows, generations, backward clocks and captures older than 30 seconds. Disabling invalidates in-flight results and clears text. Native commands also require a selected/enabled bound window and reject stopped results. Context text is marked untrusted and summaryInput separates instructions from data. The native reader consumes Theo's password-filtered accessibility inspection. Exclusions here are session/window based; Theo's app policy handles executable exclusions. Pixel OCR, region selection, automatic summarization/model invocation, and engine context consumption remain incomplete. Do not advertise those as implemented. ContextPanel and GooglePanel need mounting by the shell owner. WorkflowPanel offers local reusable command storage; executing saved commands through the engine is not wired.

WorkflowRunner journals intent before executing, prevents concurrent/restart duplicate execution for a key, exposes progress/cancel/timeout and requires verification. Cancellation/timeouts cannot retract provider writes; uncertain results remain blocked. Partial completion preserves verified step names. Local storage journals are not a multi-process atomic database; real Google writes additionally use atomic native file guards. Store commands locally only if acceptable: saved command text is not encrypted.

Verification: `node --test apps/app/src/features/workflows/workflows.test.mjs` passes four tests for staleness, in-flight cancellation, concurrent/restart idempotency and failed verification. `npm run build --prefix apps/app` passed. `cargo build --manifest-path apps/app/src-tauri/Cargo.toml` passed before the final durable-write guard; rerun recorded in task report. No live-account/native visual QA was performed.

Native owner wiring: declare google and context_bridge modules and register google_connect, google_disconnect, google_preview, google_confirm, context_bind, context_enable, context_exclude, context_read. Cargo dependencies: reqwest (blocking/json/rustls-tls), keyring (windows-native), sha2, base64, url and open. Shared wiring is coordinated with Ember, not included in this slice-only commit.

Reference: https://developers.google.com/identity/protocols/oauth2/native-app
